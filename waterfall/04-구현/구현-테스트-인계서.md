# 구현·테스트 인계서

상세 설계에서 합의한 범위를 어떤 버전으로 구현했고, QA가 어디서 무엇을 확인해야 하는지 기록합니다. 이슈, PR, CI 또는 배포 미리보기에 자료가 있으면 링크를 연결합니다.

| 항목 | 기록 |
| --- | --- |
| 프로젝트·릴리스 | [프로젝트 / 대상 릴리스] |
| 작성자·QA 인수자 | [이름 또는 역할 / 이름 또는 역할] |
| 대상 기준선 | [SRS·RTM·상세 설계의 버전 또는 승인 기록] |
| 테스트 대상 버전 | [저장소·커밋 SHA·빌드 또는 아티팩트 식별자] |
| 인계 일시·상태 | [일시와 시간대 / 준비 중·검토 중·인계 완료] |

## 1. 구현 범위

| 요구사항 ID | 구현 위치·PR | 결과 | 설계 변경·관련 변경 요청 |
| --- | --- | --- | --- |
| [FR-… / NFR-…] | [파일·모듈·PR 링크] | [완료 / 일부 구현 / 보류] | [요청 ID·승인 내역 / 해당 없음] |

각 요구사항의 구현 참조는 [RTM](../01-요구사항분석/요구사항추적매트릭스-RTM.md)에 갱신합니다. 일부 구현이나 보류의 경우 영향받는 수용 기준을 적습니다.

## 2. 빌드와 테스트 환경

| 항목 | 기록 |
| --- | --- |
| 재현 가능한 빌드·실행 | [런타임 버전, 의존성 설치·빌드·실행 명령 또는 저장소 문서] |
| QA 환경·접근 | [환경 주소, 권한 요청 경로, 담당자] |
| 환경 설정·기능 플래그 | [설정 키와 참조 위치, 테스트에 필요한 플래그 상태] |
| 데이터·마이그레이션 | [테스트 데이터 준비, 마이그레이션·시드 순서, 초기화·복구 방법] |
| 외부 연동 | [샌드박스·모의 환경 구분, 검증 가능한 범위] |

접근 자격 증명은 지정된 보관소를 통해 전달하고 문서에는 접근 요청 경로를 적습니다.

## 4. G4 테스트 인계 확인

- [ ] QA 인수자가 인계된 빌드와 테스트 환경을 식별하고 접근할 수 있다.
- [ ] 릴리스 범위의 구현 참조와 변경 결정이 RTM 또는 연결된 기록에서 확인된다.
- [ ] 구현 점검 결과와 QA에 영향을 미치는 제약을 확인했다.
- [ ] [테스트 계획서](../05-테스트/테스트계획서.md)의 진입 조건과 [단계별 검토 체크리스트](../08-검토/단계별검토-체크리스트.md)의 G4 항목을 확인했다.
